# 技能配置手册（策划侧）

这份文档是给改数值的人看的：**招式是什么、数值写在哪、改完怎么让它生效**。
不需要动 GDScript，也不要改 `scripts/` 里的任何东西。

## 1. 流水线长什么样

```text
data/skills/kaze.json       ← 你改这里（一个角色一个文件，纯 JSON）
data/skills/sora.json
        │
        │  python3 tools/skills_build.py    校验 + 生成 + 打印帧数据表
        ▼
data/characters.generated.json   ← 产物，游戏只读这个文件，你不要手改
        │
        │  scripts/skill_db.gd  启动时加载（文件坏了就用内置兜底数值）
        ▼
场上的角色：数值、判定框、连段、CPU 出招倾向
```

关键规矩：**改完必须重新生成一次。**

```bash
python3 tools/skills_build.py          # 生成，并打印一张帧数据表
python3 tools/skills_build.py --check  # 只校验：忘了重新生成会在这里失败
```

不重新生成会怎样？游戏读的还是旧的产物，你改的数字在游戏里看不到。这是这套流程里唯一
需要你记住的事，`--check` 和自动测试就是专门盯着它的。

## 2. 两分钟上手

1. 打开 `data/skills/kaze.json`（JSON 文件，用编辑器或 VS Code 都行，以 `_` 开头的键是注释，程序会忽略）。
2. 找到要改的招式，改数字。所有时间单位都是**帧**，60 帧 = 1 秒。
3. 存盘，跑 `python3 tools/skills_build.py`。
4. 看它打印的表。**命中/防御那两列就是帧优势**，正数是好的，负数是被打回来的风险。
5. 双击 `开始游戏.command` 试手感。

## 3. 角色文件结构

```json
{
  "slug": "kaze",              // 必须等于文件名，写错会报错
  "display": "KAZE",           // HUD 上的名字
  "voice_pitch": 0.9,          // 喊话音高，区分两个角色的嗓子
  "stats": { ... },            // 角色级数值，见第 4 节
  "moves": [ ... ],            // 招式表，见第 5 节
  "slots": { ... }             // 技能槽 → 招式 id，见第 6 节
}
```

## 4. stats：角色级数值

| 字段 | 含义 | 单位 |
| --- | --- | --- |
| `hp` | 血量上限 | 点 |
| `energy_max` | 气上限 | 点 |
| `energy_start` | 开局气量 | 点 |
| `energy_regen_per_sec` | 每秒自动回气 | 点/秒 |
| `energy_on_hit` | 打中对方回气 | 点 |
| `walk_speed` | 地面移动速度 | 像素/秒 |
| `air_speed` | 空中横向速度上限 | 像素/秒 |
| `jump_speed` | 起跳初速（负数＝向上） | 像素/秒 |
| `fly_speed` | 空中按住跳跃的升空速度（负数＝向上） | 像素/秒 |
| `fly_drain_per_sec` | 升空每秒耗气 | 点/秒 |
| `fastfall_speed` | 空中按防御的下坠速度 | 像素/秒 |
| `hurtbox` | 受击框 `{w, h}`，**故意做得比动画大是常规平衡手段** | 像素 |

想让两个角色手感不同，先改这里，别急着加招式。

## 5. moves：一招的完整字段

### 5.1 帧结构（动画和判定必须分离）

| 字段 | 含义 |
| --- | --- |
| `startup_f` | 启动帧，这几帧还没有判定，是「出招慢不慢」的本体 |
| `active_f` | 活跃帧，判定框存在的帧窗口，第 1 个活跃帧开始就能打到人 |
| `recovery_f` | 收招帧，判定消失后到能再动之间的硬直 |

总帧数 = 启动 + 活跃 + 收招。**判定框是数据，动画只是表现**——画面上动作对不上没关系，
帧数据说了算；这也是为什么改数值能立刻改到判定。

### 5.2 判定框

```json
"hitbox": { "x": 22.0, "y": -108.0, "w": 72.0, "h": 78.0 }
```

坐标以**脚底**为原点、+X 是角色面朝的方向、Y 向上为负。角色朝左时游戏会自动镜像。
`"hitbox": null` 表示这招本身没有近身判定（比如纯飞行道具）。

### 5.3 命中类型与音效

`kind` 决定命中音效和特效，不用自己指定音效名：

| `kind` | 含义 | 命中音 |
| --- | --- | --- |
| `light` | 轻攻击，起手快伤害低 | `hit_light` |
| `medium` | 中攻击 | `hit_medium` |
| `heavy` | 重攻击 | `hit_heavy` |
| `launcher` | 挑空，打上去能接空中追击 | `launcher` |
| `chakra` | 忍术，通常配 `projectile` | `chakra_hit` |

近身招式可以额外写 `fx_color: [r, g, b]`（每个值 0 到 1），只改变命中特效颜色，不改变命中类型、伤害或判定。未填写时继续使用按命中类型的默认颜色。

### 5.4 数值与硬直

| 字段 | 含义 |
| --- | --- |
| `damage` | 伤害 |
| `hitstun_f` | 命中硬直（对方要僵多久） |
| `blockstun_f` | 防御硬直（对方挡了要僵多久） |
| `hitstop_f` | 命中定格，双方一起停几帧，手感来源 |
| `knockback` | `{x, y}` 击退（面朝方向的相对量，y 负数向上） |
| `cost` | 出招耗气，`0` 就是不耗 |
| `cooldown_f` | 出招后的冷却帧数，防止无限连发 |
| `air_ok` | 空中能不能出这招 |

### 5.5 位移与取消（连段的命脉）

| 字段 | 含义 |
| --- | --- |
| `impulse_x` / `impulse_y` | 出招瞬间给的速度增量，突进技靠它 |
| `lunge` | 出招时的身体前倾幅度（纯表现，不影响判定） |
| `cancel_from_f` / `cancel_to_f` | 可以接下一招的帧窗口，`0` 表示不能取消 |
| `cancel_into` | 能取消成哪些招式的 id |
| `cancel_on` | `any` / `hit` / `block`：哪些情况允许取消 |

`slots.basic` 是有顺序的连击串，工具会检查「上一段能不能接到下一段」，
接不上会直接报错，不会让你在游戏里发现连段断在中间。

### 5.6 CPU 出招倾向（`ai`）

```json
"ai": { "range": 230.0, "weight": 0.8, "min_range": 60.0 }
```

| 字段 | 含义 |
| --- | --- |
| `range` | **最远**用这招的距离（比这远就不会用） |
| `min_range` | **最近**用这招的距离，可选，默认 0（贴脸时不想放飞行道具就写它） |
| `weight` | 权重，越大越爱用，`0` 等于永远不用 |

CPU 只会在「距离落在窗口内、气够、不在冷却」的招式里按权重抽一个。改这三个数字就能
把 CPU 的手感从「只会冲上来打拳」调成别的风格，不用改代码。

### 5.7 飞行道具

```json
"projectile": {
  "damage": 12.0, "speed": 880.0, "radius": 11.0, "life_f": 132,
  "knockback": { "x": 470.0, "y": -160.0 },
  "hitstun_f": 14, "blockstun_f": 12, "hitstop_f": 6,
  "hit_kind": "chakra_hit", "color": [0.72, 0.85, 1.0]
}
```

只有 `kind: "chakra"` 的招式会用它；`life_f` 是存活帧数。飞行道具的命中判定由它自己这组
数值决定，和 `hitbox` 无关。

## 6. slots：技能槽 → 招式

```json
"slots": {
  "basic":   ["punch_1", "punch_2", "punch_3"],
  "air":     ["air_kick"],
  "skill_1": ["dash_strike"],
  "skill_2": ["rising_kick"],
  "jutsu":   ["chakra_orb"],
  "ultimate": ["ultimate_strike"]
}
```

| 槽 | 玩家按键 | 说明 |
| --- | --- | --- |
| `basic` | P1 `J` / P2 `,` | 地面连击串，按顺序接，第三段通常吹飞 |
| `air` | 同在空中的 `J` / `,` | 空中那一下，要求 `air_ok: true` |
| `skill_1` | P1 `L` / P2 `/` | 1 号技能 |
| `skill_2` | P1 `I` / P2 `;` | 2 号技能 |
| `jutsu` | P1 `K` / P2 `.` | 忍术，通常是飞行道具 |
| `ultimate` | P1 `U` / P2 `K` | 超必杀，通常高伤害、高耗气、长冷却 |

规则：

- 每个槽现在只能放**一招**（`basic` 是唯一例外，它是有序的连击串）。
- 招式必须被某个槽引用，否则没人按得出来——工具会报错提醒你。
- 槽写成空数组不报错，但**那个键按下去没有任何反应**，工具会给一条警告。

## 7. 帧优势：配表真正的意义

工具打印的「命中/防御」两列是这样算的（从第 1 个活跃帧起算）：

```text
命中帧优势 = 对方命中硬直(hitstun_f)      − 攻击方剩余帧[(active_f − 1) + recovery_f]
防御帧优势 = 对方防御硬直(blockstun_f)    − 攻击方剩余帧[(active_f − 1) + recovery_f]
```

拿它对照结论：

| 帧优势 | 含义 |
| --- | --- |
| +5 以上 | 可接连段 |
| +3 ~ +4 | 可安全持续压制 |
| +1 ~ +2 | 微弱有利，能接着点，但抢不过快招 |
| 0 | 双方同时恢复 |
| −1 ~ −2 | 微弱不利 |
| −3 ~ −4 | 会被快招抢 |
| −5 ~ −7 | 会被中招确反 |
| −8 ~ −12 | 会被重招确反 |
| −13 以下 | 吃超必杀/完整连段 |
| 挑空技 / 飞行道具 | 不适用，看浮空追击窗口或距离 |

调平衡的时候不要凭感觉，先把表打出来，对着这一列看。

## 8. 加新内容

**加一招**：在 `moves` 数组里加一个对象（照抄现成的最省事），
把 id 填进对应 `slots` 里，然后重新生成。想让它能接在别的招后面，就把 id 加进那招的
`cancel_into`。

**加一个技能槽内容**：`skill_1` / `skill_2` / `ultimate` 现在都是「一招」；直接换 id 即可。

**加一个角色**：复制 `data/skills/kaze.json` 成 `data/skills/<新 slug>.json`，
改 `slug` 和 `display`，把所有招式写完，重新生成。美术素材要另外做：姿势清单在
`tools/art_spec.py` 的 `POSES`，每个角色都要在 `assets/characters/manifest.json` 里
登记，否则工具会报「这个姿势没有图」。

## 9. 工具会替你挡住的坑

改完跑一次 `python3 tools/skills_build.py`，下面这些会直接报错、且**不会生成半成品配置**：

- JSON 写错、少一个大括号（提示具体行号）
- `slug` 和文件名不一致
- 缺必填字段（帧数、伤害、`knockback`、`air_ok`、`ai` …）
- 帧数写成小数、写负数，或 `cancel_to_f` 超过了整招长度
- `pose` 不在美术清单里，或美术清单里没有这个角色的这张图
- 音效/语音名不在 `scripts/sfx.gd` 的白名单里（写错了会静音，所以宁可报错）
- `cancel_into` / `slots` 指向了不存在的招式 id，或某招没有任何槽引用它
- `basic` 串里上一段接不到下一段
- `ai.min_range` 比 `ai.range` 还大（CPU 永远不会用这招）
- 飞行道具缺 `life_f` 等字段

警告（不影响生成，但你大概想看一眼）：

- 某个技能槽是空的，对应的键按下去没反应
- 某招的 `ai.weight` 是 0
- 某招没写 `name`

## 10. 改完怎么确认真的生效

```bash
python3 tools/skills_build.py --check     # 配置没重新生成 → 这里失败

"/Applications/Godot.app/Contents/MacOS/Godot" --path . --headless \
  --script tests/skills_check.gd          # 逐条验证：配置 → 场上的角色
```

`tests/skills_check.gd` 会真的把游戏跑起来，然后检查：配置被加载（不是内置兜底）、
每个槽按下去出的是配置里的那招、场上的血量/气量等于配置、判定框尺寸和镜像正确、
自动朝向生效、CPU 只在 `ai` 窗口内选招。它失败时会直接告诉你哪一条不对。
